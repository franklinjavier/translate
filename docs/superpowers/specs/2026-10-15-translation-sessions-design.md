# Reliable translation sessions

Approved scope: implement the architecture audit recommendations while retaining the user's installed Claude and Codex CLIs. Keep Apple Translation, Local MLX, shortcuts, settings, source focus, and the anchored popover.

Each capture returns its text and replacement context together. Replacing uses that captured app, element and range, validates that the source has not changed, and never retries another mutation after an accepted but unverified write. Duplicate phrases elsewhere must not affect verification. Clipboard operations are serialized and cancellation-aware. The pasteboard can't attribute a write to its author, so a copy fallback never restores: the copied source stays on the clipboard, as if the user had pressed ⌘C. A clipboard capture snapshots app, focused element, range and value before waiting, revalidates them before posting Copy and after it returns, and, when range and value are readable, accepts only the text at that range. A paste restores the previous value only after Accessibility confirms the pasted text and only while the pasteboard still holds the paste's own write; an unverified paste leaves the translation on the clipboard and reports an attempt rather than verified success.

The coordinator owns cancellation and replacement tasks. New translations and dismissal invalidate prior callbacks and cancel active work. Retry reuses the captured request when available. Hosted tests must not install global app integrations. Tests need controllable capture, translation, and replacement boundaries without a general service container.

The CLI executor owns process lifetime, pipes/PTY cleanup, termination, and ordered output consumption. Cancellation must terminate the process and complete once, including cancellation before launch and immediate exit. Keep the existing CLI authentication and subscription flow. Codex transport output must never become translated text; if an appropriate structured event stream is unavailable, show loading until its final-message file is ready. Diagnostics contain counts and lifecycle metadata, never prompts, deltas, stdout/stderr content or user-specific executable paths.

Local MLX must validate terminal state and reject truncation, server errors after deltas and premature EOF. One four-case runtime engine selection replaces the backend/Apple precedence pair; decode legacy settings and preserve previous-engine restoration explicitly.

Keep behavioral translation examples and checks. Separate the offline tests, opt-in evaluation runner, and corpus. Remove tests coupled to incidental prompt wording. Document a normal offline verification command. Retain exact-selection geometry, screen clamping and focus behavior; conservatively invalidate stale drag hints after keyboard navigation. Keep manual popover sizing unless a measured compatible alternative is demonstrated.

Success requires offline regression evidence for repeated text, changed selections, clipboard ownership, cancellation, superseded requests, CLI lifecycle and malformed/truncated streams, plus a fresh complete build/test run. No API migration, new paid service, publication, push, merge, or app installation is part of this implementation request.
