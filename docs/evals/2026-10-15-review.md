# Translation quality review, 15 October 2026

Codex ran real translations through Translator, including streaming, PromptBuilder and OutputSanitizer. Inputs are synthetic work-chat examples, never personal documents.

## Findings

- The old prompt reproduced the screenshot defect: “Like Notion and Obsidian had a baby.” became “Notion and Obsidian had a baby.” The 12-case baseline is in `2026-10-15-before.json`.
- Added 39 scenarios: 12 English proofreading, 15 Portuguese to English, 12 English to Brazilian Portuguese. Checks allow valid alternatives and test their own accepted/rejected examples. Source instructions are treated as text.
- The selected prompt preserves natural fragments and comparisons, explicitly protects uncertainty, actors, literal commands/URLs and Markdown, and frames the source as data. Exact eval source sentences are excluded from the system prompt.
- Claude CLI, model alias `sonnet`: 39/39 automatic checks passed. Codex also read all 39 input/output pairs. Comparison, negation, uncertainty, code/flags, timelines, questions and timestamps were preserved. This is a finite sample, not a claim of parity with Raycast.
- Local MLX, Qwen3-4B-Instruct-2507-4bit: the stored run originally passed 36/39. One rejection (“What if … had a kid”) was a valid conditional comparison and the checker now accepts it. Two genuine weaknesses remain: “I could be wrong” became an assertion of being wrong, and literal `14:00`/`15:30` became `14h`/`15h30`. A follow-up prompt variant fixed uncertainty but regressed other cases, so it was rejected. Do not describe the local eval as fully passing.
- Several checker false positives were corrected with accepted-variant examples, without accepting the wrong negation, actor, conditional or literal command. Naturalness still requires human review; keyword presence is not a complete meaning check.

## Reproduction

See `../translation-eval.md`. Run the opt-in live suite with Local or `TEST_RUNNER_TRANSLATION_LIVE_BACKEND=claude TEST_RUNNER_TRANSLATION_LIVE_MODEL=sonnet`. Failures must stay visible. Default offline tests do not contact an engine.

The selected backend in the user's app was not changed by these evaluations. Choose Claude in Settings if preferring the backend that passed this sample; Local remains available offline.

## Related UI verification

The screenshot overlap now uses AX full-range plus first/last-character bounds, ancestor/text-marker queries, and a same-app remembered drag fallback independent of later pointer movement. Drag bounds are an estimate when AX supplies no geometry; keyboard-only selection in unsupported apps can still fall back to the pointer. Shortcuts use white at 70% opacity. Settings uses ID-based row bindings to prevent stale array-index access after deletion. Codex ran 101 offline tests including selection geometry, real hosting-view sizing and stale-binding add/edit/remove cycles; all passed.

The installed Settings window was also tested through its real UI: add a temporary language, edit its name/destination, remove it, and confirm the app stays open with the original languages intact. Frank supplied a screenshot of the actual multiline selection and popover for the README.
